\section{Description}

The task is to implement a dictionary based on the PATRICIA tree (Practical Algorithm To Retrieve
Information Coded In Alphanumeric).

A PATRICIA tree is a compressed binary trie in which every node stores the index of the critical
bit of the key that is used for branching. This avoids chains of single-child nodes and keeps the
height of the tree at $O(\log n)$ on average for random keys.

The key feature of the structure is \textit{back edges}: when during a descent the critical bit
index of the next node does not exceed the index of the current node, the descent stops. The
target node of such an edge is the candidate for a full string comparison.

To handle boundary cases correctly, a header node (\texttt{header\_}) with a zero critical bit is
used; its left child is the root of the tree. All keys are converted to lower case, which makes the
dictionary case-insensitive. The dictionary supports the operations \texttt{insert},
\texttt{find}, \texttt{remove}, as well as binary \texttt{save} and \texttt{load}.

\section{Source code}

\subsection{Helper functions}

The function \texttt{extractBit} extracts the $i$-th bit of a string (numbering starts at 1, the
most significant bit of the first byte is bit 1). The function \texttt{firstDifferentBit} finds
the position of the first bit in which two keys differ; the result is used during insertion to
determine the critical bit of the new node. The functions \texttt{writeUnsigned} and
\texttt{readUnsigned} write and read unsigned integers of a given width in little-endian byte
order. The public free function \texttt{isValidKey} checks that a key consists only of English
letters and has length from 1 to 256, and \texttt{normalizeKey} converts a key to lower case.

\subsection{Node structure and the trie class}

Every node stores a key, a value, the critical bit index and pointers to two children. The field
\texttt{size\_} of the class \texttt{PatriciaTrie} tracks the number of elements. The node type is
a private nested structure \texttt{PatriciaTrie::Node}; the class owns its nodes, so copying is
disabled and only moving is allowed.

\subsection{Search}

The method \texttt{searchNode} descends the tree, choosing the branch by the critical bit, until it
meets a back edge (the bit index of the next node is $\leq$ the index of the current one). The node
found is a candidate for which \texttt{find} performs a full string comparison and returns the
value wrapped in \texttt{std::optional}, or \texttt{std::nullopt} if the keys differ.

\subsection{Insertion}

During insertion \texttt{searchNode} is executed first to detect a collision or to obtain a
reference key. The function \texttt{firstDifferentBit} computes the critical bit of the new node.
Then a second descent is performed down to the position where the new node must be inserted,
after which the node is attached with a back edge to itself.

\subsection{Removal}

The method \texttt{remove} handles two cases. If the node being removed has a back edge to itself
(a leaf node), \texttt{removeNodeWithSelfLoop} switches the parent link, found by
\texttt{findParentLink}, to the other child. Otherwise the back edge to the node comes from another
node (the holder): \texttt{removeNodeWithoutSelfLoop} moves the data of the holder into the node
being removed, updates all links that pointed to the holder and physically deletes the holder.

\subsection{Serialization}

The file starts with a header: the 8-byte magic string \texttt{PATRICIA}, a 4-byte version number
(currently 1) and an 8-byte number of entries. The method \texttt{saveSubtree} traverses the tree
recursively and writes every node as a triple: key length (2 bytes), the key itself and the value
(8 bytes). All integers are stored in little-endian byte order. Two bytes are used for the length
because by the statement a key may be 256 characters long, and one byte is not enough for this
value.

The method \texttt{load} checks the magic string and the version, reads exactly the declared number
of entries, validates every key (length, English letters only, lower case, no duplicates) and
requires that no extra bytes follow the last entry. Entries are inserted into a new tree through
\texttt{insert}. The method \texttt{loadFromFile} replaces the current state with the loaded tree
through \texttt{swap} only after the whole file has been read successfully. Any error is reported
with a \texttt{PatriciaError} exception: \enquote{cannot open file for writing}, \enquote{cannot
open file for reading}, \enquote{failed to write file}, \enquote{invalid file format},
\enquote{unsupported file version}. In this case the working dictionary remains unchanged. The
method \texttt{destroySubtree} frees the nodes recursively in the destructor and in
\texttt{clear}.

\subsection{Command processing}

The class \texttt{Dictionary} parses one input line in the method \texttt{execute}: the line is
split into tokens, the command is determined by the first token, keys are checked with
\texttt{isValidKey} and normalized with \texttt{normalizeKey} before being passed to the tree. The
responses are \texttt{OK}, \texttt{Exist}, \texttt{NoSuchWord} and \texttt{OK: N}. Errors are
reported with the lines \texttt{ERROR: invalid command}, \texttt{ERROR: unknown command},
\texttt{ERROR: invalid key}, \texttt{ERROR: invalid value}, and for file commands with the text of
the \texttt{PatriciaError} exception prefixed by \texttt{ERROR:}. The function
\texttt{runDictionary} reads commands line by line and prints a response for every non-empty
line; if memory allocation fails, it prints \texttt{ERROR: out of memory}. The function
\texttt{main} only calls it for the standard streams.
