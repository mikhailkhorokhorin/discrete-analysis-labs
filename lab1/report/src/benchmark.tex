\section{Performance test}

\subsection{Method}

For the comparison, two identical arrays of randomly generated dates are created
(\nolinkurl{lab1/benchmark/benchmark.cpp}). One of them is sorted by the implemented
\texttt{radixSort}, the other by the standard function \texttt{std::stable\_sort} from the STL.
The time of each algorithm is measured separately with \texttt{std::chrono::steady\_clock}.
Data generation and input/output are not included in the measurement.

The test is run for five sizes from $100$ to $10^6$ elements.

\subsection{Analysis of the results}

For small inputs ($N = 100$) both algorithms finish in a fraction of a millisecond, and the
overhead is comparable to the useful work, so the difference is negligible.

Starting from $N = 1\,000$, radix sort is consistently faster than \texttt{std::stable\_sort}.
This agrees with the theoretical estimates: the complexity of \texttt{radixSort} is $O(n \cdot k)$,
where $k = 4$ is the fixed number of bytes in \texttt{std::uint32\_t}, that is, effectively $O(n)$.
The complexity of \texttt{std::stable\_sort} is $O(n \log n)$.

For $N = 10^6$ radix sort is \textbf{1.36 times} faster (140\,767~$\mu$s
versus 191\,842~$\mu$s). The gap is smaller than one might expect from a linear algorithm,
because \texttt{radixSort} makes 4 full passes over the array (4 passes over memory in total),
while \texttt{std::stable\_sort} uses cache-friendly block operations.
Nevertheless, the linear asymptotics is confirmed: when $N$ grows 10 times, the time of
\texttt{radixSort} grows about 10 times, while \texttt{std::stable\_sort} grows slightly faster.
