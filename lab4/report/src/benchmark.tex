\section{Performance test}

\subsection{Method}

The test compares the implemented Knuth--Morris--Pratt algorithm with naive search.
For each position of the text the naive algorithm checks the pattern symbol by symbol,
so in the worst case it runs in $O(|P| \cdot |T|)$.
KMP builds the prefix function and then scans the text once, which gives
$O(|P| + |T|)$. The benchmark measures the same \texttt{KmpMatcher} that the application uses
(through \texttt{kmpSearch}).

Two series of experiments are carried out. In the first series a random text is generated over
an alphabet of 10 random numbers, the pattern length is 8. The second series uses the worst case
for naive search: the pattern consists of 19 ones followed by a two,
and the text consists only of ones.

The search time is measured with \texttt{std::chrono::steady\_clock}.
Data generation and input reading are not included in the measurement. After each run the
benchmark compares the full lists of found positions for KMP and the naive algorithm.

\subsection{Analysis of results}

On random data naive search usually stops checking after the first or second number of the
pattern, so its practical running time is close to linear. Because of this KMP gets no noticeable
advantage: in some runs it is slightly faster, in others slightly slower due to the additional
accesses to the prefix function.

In the worst case the difference becomes significant. For $|T| = 5\,000\,000$ the naive
algorithm takes \textbf{55\,733 $\mu$s}, while KMP takes \textbf{11\,924 $\mu$s}, that is,
KMP is about \textbf{4.7 times} faster. This agrees with the theoretical difference
between $O(|P| \cdot |T|)$ and $O(|P| + |T|)$. The KMP time for $|T| = 100\,000$ is higher than for
$500\,000$: a run of about a millisecond is dominated by measurement noise (cold caches and the
first access to freshly allocated memory), so the comparison relies on the larger sizes.
