\section{Description}

The task is to implement the Knuth--Morris--Pratt algorithm for finding one pattern
in a text over the alphabet of numbers from~0 to~$2^{32}-1$.

The KMP algorithm runs in $O(|P| + |T|)$, where $|P|$ is the length of the pattern and $|T|$ is
the length of the text. First, the prefix function $\pi$ is built for the pattern: the value
$\pi[i]$ is the length of the longest proper prefix of $P[0..i]$ that is also a suffix of this
sequence. Then the text is scanned from left to right. On a mismatch the algorithm never moves
back in the text; instead it uses $\pi$ to choose the next length of the already matched prefix.

Numbers are read into the type \texttt{Token}, an alias for \texttt{std::uint32\_t}, with
\texttt{std::from\_chars}. Numeric parsing handles leading zeros correctly: \texttt{0011} and
\texttt{11} become the same value~11. A token that is not a number or does not fit into
$[0, 2^{32}-1]$ is not truncated silently: the program prints
\texttt{ERROR: line N: invalid token 'x'} (or \texttt{ERROR: pattern: invalid token 'x'} for the
pattern line) to the standard error stream and exits with code~1.

\section{Source code}

\subsection{Prefix function}

The function \texttt{buildPrefixFunction} builds the array $\pi$ for the pattern. The variable
\texttt{length} stores the current length of the matched prefix. While the next symbol does not
match, \texttt{length} falls back along the already computed values of the prefix function.

\subsection{Matcher}

The class \texttt{KmpMatcher} holds the pattern, its prefix function and the length of the
matched prefix \texttt{matched\_}. The method \texttt{feed(token, position)} processes one
token of the text together with its position (a \texttt{Position} structure with the fields
\texttt{line} and \texttt{word}) and returns \texttt{std::optional<Position>}: the position of
the start of an occurrence if the pattern has just been matched, and \texttt{std::nullopt}
otherwise. To report the start of an occurrence without storing the whole text, the matcher
keeps a ring buffer \texttt{window\_} of the positions of the last $|P|$ tokens. The method
\texttt{reset()} clears the state before a new text.

\subsection{Search}

In the main program the text is processed as a stream, line by line and word by word, in
\texttt{runSearch}. This matters because the statement has no limits on the length of the text,
while the memory limit is 64 MB. Each token is passed to \texttt{KmpMatcher::feed}, so occurrences
that cross line boundaries are found naturally. The function \texttt{kmpSearch} is built on the
same \texttt{KmpMatcher} and is used by the benchmark, so the benchmark measures exactly the code
used by the application.
